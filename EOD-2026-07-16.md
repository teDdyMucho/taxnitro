## Summary

Built a **Required Documents** feature end-to-end for both the Tax and Bookkeeping categories. Clients now upload against a specific required checklist item, admins approve with a read-only view of what the client selected, and the dashboard progress checklist reflects live status (grey → yellow → green). Also fixed two bugs surfaced during testing (file-reply 400 error, stale "Pending" state on reject/delete).

---

## What shipped today

### 1. New "Required Documents" folder in both categories
- Added a **Required Documents** folder to **Tax** and **Bookkeeping**, mirroring the existing "Client Uploads" pattern (gold cloud-upload icon).
- New folder keys `tax_required_documents` and `bk_required_documents` registered across all 6 config locations (folder tables source-of-truth, client Documents screen, admin file browser, admin dashboard, admin filters, reply-bell labels).
- New Supabase tables created via migration (matching the existing folder-table schema + RLS).

### 2. Requirement picker on upload (client)
- Uploading into a Required Documents folder now shows a **"What are you uploading?"** checklist **first** — the client picks which required item the file is for, then selects the file.
- **Category-specific lists:**
  - **Bookkeeping** → 4 BK items (Bank Statements, Credit Card Statements, Loan Statements, Payroll Reports)
  - **Tax** → 2 CFO items (Prior Month Bookkeeping / QBO Access, AR / AP Aging)
- Driven by a single `FOLDER_REQUIREMENT_SERVICES` map for easy future edits.

### 3. Three-state progress radios (dashboard)
- The dashboard "Required Documents" checklist now shows three states:
  - ⚪ **Grey** — not uploaded
  - 🟡 **Yellow / "Pending"** — client uploaded, awaiting admin approval
  - 🟢 **Green / "Accepted"** — admin approved
- Backed by a new `status` column (`pending` / `approved`) on `document_requirements` + client insert/update RLS.

### 4. Read-only admin approval
- The admin **Approve Upload** modal no longer forces a manual pick — it now **shows the item the client already selected** (read-only) and just approves. Approval flips the slot yellow → green automatically.
- Manual picker retained as a fallback for legacy/untagged uploads.
- Fixed a one-frame flash where the previously-approved doc's tag briefly showed on open.

## Bugs fixed

| Bug | Cause | Fix |
|-----|-------|-----|
| **Reply to file feedback returned 400** | `file_conversations` insert error was silently swallowed; likely an old `folder_table` CHECK constraint excluding the new folders | Surfaced the real error via Alert + restore text; wrote `file_conversations.sql` migration to drop the restrictive constraint & fix RLS |
| **Radio stuck on "Pending" after reject** | Rejecting a doc never cleared the pending requirement row | `clearPendingRequirementForDocument` called on reject |
| **Radio stuck on "Pending" after delete** | Deleting a file (client or admin) never cleared the pending row | Cleanup wired into both delete paths + new client DELETE RLS policy |
