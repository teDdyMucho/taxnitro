## Summary

Reworked the client/staff document logic per the new "suites" spec, restructured the upload model (single client upload entry point, staff-only deliverable folders), added an admin all-folders upload flow, embedded the Financial Reports tool full-screen with FTG colors, and fixed several dashboard/tagging bugs.

## What shipped today

### 1. Monthly Reporting restructure (BK + CFO)
- "Monthly Reporting" is now a **nested group** you tap into → **Required Info · For Client Review · Final Statements**.
- **Required Info** (client uploads): client picks a required item (Bank Statements, Credit Card, Loan, Payroll; CFO also Prior Month Bookkeeping/QBO + AR/AP Aging); the label is prefixed onto the filename; docs are grouped by **month section headers** (JULY 2026 …); progress tracking preserved.
- **For Client Review / Final Statements** (staff uploads): staff picks a label (Query Sheet / P&L / Balance Sheet; Final adds FINAL P&L, Balance Sheet, Cash Flow, KPI Dashboard, TLDR, Budget vs Actual for CFO). Client only views / approves / rejects.

### 2. Client upload model — single entry point
- Removed the per-folder Upload button from **all** client folders (read/view only).
- Added one **"Upload" button in the client sidebar** (desktop + mobile) → `ClientUploadModal`: client picks a TAX folder (Tax Contracts, Tax Invoices, Client Uploads, Additional Tax Docs, Tax Returns) then the file. Everything else is staff-delivered.

### 3. Admin/staff — upload to any folder, any client
- New **Upload** button on the admin "All Documents" screen → `AdminUploadModal`: pick client (searchable) → pick any folder (all TAX/BK/CFO) → pick file. Tagged `uploaded_by_role = staff/admin`.

### 4. Financial Reports tool
- Embedded **full-screen** (over the app shell) with a **"Back to Admin"** button injected into the report's own sidebar (above the user card).
- Recolored the report to the **FTG palette** (gold + dark brown, no black bands).

### 5. Dashboard fixes
- **Service labels**: CFO items were mislabeled "TAX" (3-service `serviceLabel()` helper — BK→Bookkeeping, TAX→Tax, CFO→CFO).
- **Tag counts now count as numbers**: a Required-Info collector folder's count = sum of its item tag counts, so Required Info / Monthly Reporting / category totals stay consistent with the item breakdown.
- **View tagged files**: tapping a required item (e.g. Bank Statements) opens a modal listing the actual tagged files (name, client, date, status) — each opens the document.

### 6. Bug fixes
- Approve-Upload modal: fixed the BK/CFO double-select (same `key`) — selection now keyed by `service:key`; tagging kept for all docs.
- Doc detail page: centered + width-capped card on desktop (full-screen on phone).

### 7. Client upload note ("what is this file for")
- Added an optional **Note** field to the client upload modal (`ClientUploadModal`). When filled, it's saved as the **first message** in the file's `file_conversations` thread (`sender_role = client`) — staff can read and reply. Blank is allowed; the note never blocks the upload.
- Surfaced the note on the **admin/staff side** in two places:
  - **Approve Upload modal** — a "Client note" card at the top (fetches the client's first message) so staff see the context *before* approving/tagging.
  - **All Documents rows** — a new **notes (💬) button** next to view/delete opens the full `FileConversationPanel` for that file, where the note shows and staff can reply.
- No new SQL — reuses the existing `file_conversations` table + RLS (client insert allowed when `sender_id = file_owner_id = auth.uid()`).
